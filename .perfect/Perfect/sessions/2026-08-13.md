  - AC1 ✓ `TELEMETRY_FLUSH_INTERVAL` = 120s wall clock, with the choice *argued*

    the right unit when the thing being bounded is an interruption; a page stride

    `http_lost`** (`crates/core/src/tiers.rs:128-138`). I verified this myself.
    The pre-existing call passed a hardcoded `"http"` for every host, so **a host
    that bot-walled the entire run had its strike count cleared by the very call
    whose purpose is to teach the router which hosts bot-wall** — and, since
    `tier_memory` is keyed by host alone, it cleared what *other apps* had learned
    about that host too. Fixed with `tier_that_won(http_lost)` plus a monotone
    per-run `lost` set, so a completed run's final signal is identical to the
    single end-of-run signal it replaced. **This bug was not in the brief.**
  - AC3 ✓ `is_page_fetch` — named predicate, and the residual case
    (a robots-declared sitemap at a non-sitemap-looking URL) is documented rather

  - AC4 ✓ `runs` / `runs_complete` / `partial`, with `add(.., 0)` used
    deliberately so both keys are always PRESENT — an absent `runs_complete`
    would make a reader unable to distinguish "no run finished" from "this record
