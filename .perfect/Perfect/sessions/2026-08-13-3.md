**D2 `http-transport-errors-terminal` + D3 engine half — `2e46fd0`.** *Process deviation,
flagged by the builder rather than papered over*: the two directions could not be split into
separate commits (both live in `engine-http/src/lib.rs`, D3's jar work had started before D2's

commits build and pass standalone. **Accepted** — the skill's own guidance is to commit by file
boundaries and document the shared commit when directions interleave in one file, which is
exactly what happened. Honesty here is worth more than the atomicity.
The classification itself is the best engineering in the wave: `TransportPredicates`, a
struct-of-bools lifted off `reqwest::Error`, **because `reqwest::Error` has no public
constructor** — so a classifier taking one could only be exercised through a live socket, and
the cases that matter most (TLS mismatch, NXDOMAIN) are precisely the ones a loopback test
cannot produce. Splitting the rule out makes every combination testable. Exactly one class is
deterministic (`is_builder` → `Error::BadRequest`, already terminal, **nothing widened, so no
variant audit needed**), and the exclusions carry more reasoning than the inclusion: `is_connect`
stays retryable because it bundles NXDOMAIN-from-a-down-resolver, a captive portal failing TLS,
and a restarting service, with no predicate separating them. Verified against reqwest 0.12.28
source *and* a live test. The battery gained a second fixture with `retries: 2`, so the ladder
is no longer switched off — and the transient row is pinned `false` on purpose, because
over-classification is this fix's failure mode.

**D3 `profiled-fetch-is-honest` — `2e46fd0` + `3c806b1`.** Lever (b), and the reason is one I
had flagged as a *risk* and they turned into the deciding argument: `fetching.md:230` documents
establishing a login by "driving a login POST on the HTTP tier", which **is** a profiled fetch
with no jar — so refusing at the seam would break the tier's own onboarding path. Instead: WARN
at load, plus a reserved `x-pumper-anonymous-profile` header written **both ways round on every
profiled response** (so an origin cannot forge it) and read only when the caller asked for a
profile. `sent_anonymous` is captured *before* `send`, because a login response's own
`Set-Cookie` would otherwise mask the fact that this request carried nothing — a subtlety
neither the brief nor the scout named. Criterion 2 closed by moving `create_dir_all` from load
to the first save that has a cookie, verified against `GET /profiles` enumerating directories.
`save_decision` is a three-way enum whose doc **states the cost of the rule honestly**: a
genuine logout no longer erases the stored jar, so a dead cookie survives until the next login —
the cheaper failure, since the site rejects a dead cookie whereas a clobbered session has no
recovery. `3c806b1` lifts the marker into the escalation trail and `TierTrace.detail`
**including the winning entry** (the winning fetch is the one about to be stored) and, as a
bonus, replaces two hand-rolled `detail` match arms with one `http_tier_detail` renderer so a
third note could not drift between them. `Error::Profile` correctly left non-terminal.

### Builder refutations — four load-bearing, all Director-verified before acceptance

1. **`extract_yields` attribution — my criterion was wrong.** `YieldEntry.dataset` is the
   dot-joined *key path* (`costs.rs:189-193`), `""` at root, and `walk_yields` **keeps
   descending below a match** — so nesting the summary under a dataset-named object would make
   the run report its counts twice. Verified in source. They emitted `dataset` anyway (it is
   what a human or agent reading `GET /jobs/{id}` needs) and pinned what is actually true:
   exactly one yield entry, right counts, no double-count. Note `extractor` has shipped that
   field since r12 and is attributed to `""` too — so this was never a plugin-app defect.
2. **`DerivedPaths` takes dot-separated names, not JSON pointers.** My criteria specified
   `/run_at`, `/avg_elapsed_ms`, …; `DerivedPaths::new` filters empty strings and resolves
   `.`-separated names, so a leading `/` is a **silent no-op**. The seam would have looked
   adopted and done nothing — which is precisely the failure class the direction existed to
   kill. Verified at `datasets.rs:3757-3768`.
3. **`drift_score` must be derived, not "argued either way".** With it in the identity the
   behavioral criterion *cannot* pass: run 1 writes `null`, run 2 writes `0.0`. They hit it as a
   real red test. Safe to derive because it is a pure function of `rates`, which stays in.
4. **The "apps depend only on core" rule is false as written** — and broader than they found.
   Measured: **five** app crates violate it (census-bfs/nesd/nonemp → `app-census-density`,
   cordis → `app-eu-sedia`, extractor → `app-crawl` **and** `pumper-engine-archive`). They
   correctly refused to follow the precedent and copied `parse_records_echo` instead. Carried as
   Director commit `3df377d`.
