## Director verification before the gate — two claims changed, and both changes mattered

- **`research`'s "reports success on failure" class: NARROWED.** The scout read the whole class as
  broken. It is not — `budget_exhausted` carrying real partial text is *correct*, the user paid for
  those findings, and the test pinning it is a RIGHT test. The genuine lies are the **empty** case and
  `is_report_shaped` stamping a content-free report `completed`. The narrowing went straight into the
  acceptance criteria as "this test must keep passing", and it did.
- **The search-eviction finding: PARTIALLY REFUTED.** Every research run's search doc deletes every
  prior run's, and the scout called it the worst possible retention policy. Reading `worker.rs:1918-1928`
  showed the `_job` sweep is a *deliberate, documented* ghost-doc GC, correct for apps whose `_job` doc
  is a run summary. Research is simply the one app where that doc **is** the product. Reframed as
  app-side, which reopens the `CATALOG_EXEMPT` question — so it was banked rather than slated.
- **Two claims came back SHARPER.** `max_budget_usd`'s own param text literally reads *"per-run Claude
  spend ceiling"* while the value is set on every one of 12 calls. And `state-tax`'s comment says it
  routed through `sync_many_with_provenance` *"so the degrading-source removal guard still applies"* —
  while `enforce` is off by default **and** the family makes zero `observe_extraction` calls, so the
  guard it deliberately reached for cannot engage.
