## The wave — 2 lots, 6 directions, 0 builder deaths

Grouped by write set into two pairwise-disjoint lots. The trigger family had to be ONE lot
because all three of its directions touch `e2e/trigger_plugins.rs` — the disjointness criterion
choosing the grouping, exactly as the doctrine says.

**Lot A — trigger family** (`9256ddd` → `ce9652c` → `fd88138`, built in that order because D3
is the harness D4's test needs):
- **The twice-banked enabler shipped.** CI now builds all four detached `plugins-src` crates
  for wasm32 and runs the artifact tests; `just plugins-install` globs all four and owns the
  `title_extractor.wasm` → `title.wasm` rename that lived only as README prose. **The builder
  refuted the naive design**: deleting `#[no_mangle]` from an export *still compiles clean for
  wasm32*, so a build-only CI step would not have caught an ABI break. Two guards instead —
  a source-level EXPECTED-diff ABI test in the ordinary suite, plus the artifact tests asking
  the host whether each module is executable.
- **trigger-gate stopped vetoing every job and external hop.** A rule whose field is *absent*
  is now inapplicable, not failed. Its two new artifact tests **FAILED against the previously
  installed `.wasm`** — the pair relationship paying off exactly as r22 predicted.
- **Work scope became host-owned.** `PROVENANCE_KEYS` → `HOST_OWNED_KEYS` with two classes,
  and the sharpest distinction of the round is the builder's: dropping a *lineage* key is not
  an override (it is the normal shape of a keep-list transform), but dropping a *work-scope*
  key is, **because absence is itself an instruction**. Also fixed the pre-existing host
  truncation that silently lost record #(cap+1). First test anywhere to assert the **enqueued
  job's** `params._trigger` rather than the hook verdict.

**Lot B — engine + fleet honesty** (`5ea0670`, `de3af27`, `fc5f46b`):
- **A cancel now kills the process tree.** `RunScope`'s `Drop`, mirroring engine-browser's
  `RenderScope`. **This corrects an overclaim in r13's own ledger**, which recorded
  `claude-kill-tree` as covering "a timeout/**cancel**" — the cancel half was never true.
- **A `year_from` window can no longer tombstone what it merely scoped out.** The builder
  improved on the brief: the guard keys on what the window **actually excludes**, not on
  `year_from.is_some()`, so a window excluding nothing keeps full-snapshot semantics and a
  consumer pinned at 2016 still sees a month retired. Its `alternating_windows_do_not_flip_
  the_shared_dataset` test reproduces the ~10 GB re-download churn loop, not merely the delete.
- **Schema drift is terminal.** `Error::SourceDrift`, pinned per crate by an EXPECTED-diff
  inventory test separating `EXPECTED_TERMINAL` from `EXPECTED_RETRYABLE`.

## The builder refusal that earned the round

Lot B's `Error::SourceDrift` forced an arm in `routes/error.rs::client_facing` — an exhaustive
match with **no wildcard, by design** — which sat in *neither* lot's write set. The builder:
(a) did not leave the workspace uncompilable for its sibling, (b) chose the **provable no-op**
(group with `E::App` in the 500 bucket, leaving the HTTP surface byte-for-byte unchanged), and
(c) escalated the merits with a recommendation rather than deciding. Ratified to 502 —
the 502 arm's own comment is *"Somebody else's failure, reported as such rather than as ours"*,
and a source renaming a field is definitionally not our bug.

**And it surfaced an invariant the direction's own pre-flight missed.** I checked before
accepting that `Error` is not `#[non_exhaustive]` and that `is_terminal_for_job` is a `matches!`,
and concluded "purely additive". It is not: **adding a `pumper_core::Error` variant requires an
arm in `crates/server/src/routes/error.rs::client_facing`.** Recorded in that commit message.
